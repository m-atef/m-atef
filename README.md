## 🧭 What I Do Now

I'm a **Senior Software Architect**. I design enterprise systems, own the technical direction, and make sure the thing we ship on Monday is still boring in production by Friday.

## 🧩 Architecture Principles I Actually Enforce

```text
Readable code          >  clever code
Explicit contracts     >  assumptions
Small services         >  god services
Logs that answer       >  logs that ask
Indexes                >  blaming the server
Retry + dead-letter    >  manual reprocessing
Documentation          >  "ask Ahmed"
Incremental migration  >  the Big Rewrite
```

What I optimize for, in order:

| Priority | Means |
|:--|:--|
| ✅ **Boring in production** | No surprises at 2 AM. Predictable failure modes. |
| ✅ **Observable** | Every workflow can be traced end-to-end from Seq without a debugger. |
| ✅ **Maintainable** | The next developer, who is probably future me, understands it in one sitting. |
| ✅ **Testable where it matters** | Business rules and integration contracts, not framework plumbing. |
| ✅ **Fast enough for real workloads** | Measured with query plans and load, not vibes. |

## 🎭 Things I Enjoy Designing

### 🔄 Integration Architecture
Systems that connect other systems which were never designed to be connected. Idempotent handlers, versioned contracts, explicit dead-letter states, and a retry strategy for every hop.

### 🧠 Actor-Based Workflows
**Akka.NET** when a system needs clear responsibility boundaries, long-running coordination, or stateful background work that shouldn't block the application. The whole contract fits in one sentence:

> "You handle this. Tell me when you're done. Don't block the whole application."

### 🏭 Industrial & Hardware Communication
Sometimes software talks to browsers. Sometimes it talks to PLCs. Sometimes the PLC talks back.

Sometimes the PLC says nothing and you spend three hours checking rack, slot, byte, bit, cable, firewall, and your life choices.

### 🗄️ Databases That Scale With the Business
Actual SQL — not "select everything and filter in memory." Proper indexes, paging, DTO projections, Dapper where it matters, EF Core where it fits, query plans when things get suspicious, and no distributed transactions unless forced by dark magic.
